# MTA Audio Editor 0.3.0-r210 - VST3/MIDI completion

## IT

Editor originale sul server: aprire la configurazione del plugin e scegliere Editor originale. Mouse, tastiera e rotella controllano la stessa istanza live, anche nel bus di monitoring VSTi. Una sessione in pausa viene creata se manca il playback. Alla chiusura lo stato viene salvato con controllo del proprietario, quota e conflitti; scadenza/chiusura della sessione tenta il salvataggio. Un plugin bloccato non garantisce il recupero delle modifiche non ancora salvate. Nessun VNC pubblico, clipboard remota o upload di eseguibili.

RPM/DEB includono Xvfb 21.1.24 privato compilato da sorgente ufficiale con SHA-256 bloccato (scripts/build_server_display.py), necessario anche su EL10 dove il package Xvfb standard è stato rimosso. Non richiedono repository non ufficiali; il manifest e la licenza MIT/X11 sono nel package. Docker usa Xvfb della distribuzione. È inclusa libXtst; il kernel/container deve permettere Landlock ABI >=3. Il worker GUI elimina le credenziali dall’ambiente e limita l’accesso ai runtime, ai plugin fidati, alle sorgenti autorizzate e alla cartella temporanea privata. In assenza di confinamento, l’editor originale non viene abilitato. I test grafici in questo ambiente usano un display TCP con cookie e bypass di confinamento esplicitamente di test, poiché AF_UNIX e Landlock non sono disponibili: questo non certifica il confinamento del server reale. Non configurare MTA_VST3_DISPLAY_TEST_TCP nel servizio di produzione. Il kernel/criterio LXC effettivo resta da verificare.

Runtime Pedalboard 0.9.26+mta2 costruito dal commit upstream bloccato, con patch verificate e hash di tutti gli header nel manifest di build. ABI 2 aggiunge PPQ continuo/mappe a zone/adattive, bus sidechain esterno e traduzione UMP a eventi VST3. Si ricostruisce durante il packaging, mai all’avvio. L’app rimane 0.3.0-r210. I plugin devono essere binari Linux fidati della stessa architettura del server, installati dall’amministratore.

Sidechain: traccia pre-insert dopo il gain, bus ausiliario selezionato e gain del send. Il grafo condiviso è usato anche dagli export e dai bounce. Senza C++ la richiesta viene rifiutata esplicitamente. Il plugin di prova sorgente in tests/vst3_probe rende deterministico il confronto live/offline e non include sorgenti vendor o binari.

MIDI: SMF tipo 0/1 conserva SysEx completi (64 KiB per pacchetto, massimo 1024 e 8 MiB totali), senza ripeterli al seek. I/O hardware SysEx richiede attivazione esplicita e, sul web, il consenso del browser. MPE lower/upper configura RPN e alloca i canali membri. MIDI 2 usa libremidi nativo con endpoint UMP dell’OS; se mancano, viene segnalato e non viene dichiarata una conversione MIDI 1 come UMP nativo. MTA UMP JSON conserva parole/timing; non è lo standard SMF2. Il bridge VST3 supporta note on/off, velocity 16 bit, pressione e CC/pitch/channel pressure 32 bit, per-note pitch bend e gli ID note-expression MIDI 2 del namespace VST3 3.8. I messaggi senza mapping host vengono rifiutati per il VSTi, ma possono essere conservati e inviati all’hardware. La risposta dipende anche dalle note-expression implementate dal plugin. Il pitch bend per-note usa l’intervallo predefinito di 48 semitoni. SMF tipo 2/SMPTE e selettore ASIO dedicato non sono stati introdotti.

Audio esterno: pulsante rosso nella barra transport, scelta ingresso e nome, compensazione latenza, Play opzionale. Nel browser richiede HTTPS/localhost e permesso microfono. Nativo: miniaudio C++ con ring SPSC; browser: AudioWorklet. PCM stereo float con sequenza e dimensione verificate viene caricato a pacchetti. Default 512 MiB, massimo un’ora, una cattura per utente e sedici globali; MTA_AUDIO_CAPTURE_LIMIT_BYTES è configurabile tra 1 MiB e 4 GiB. Le sessioni abbandonate scadono dopo 45 secondi. Le quote restano applicate e la traccia è aggiunta usando il journal/import transazionale esistente, prima della notifica. Collegare fisicamente l’uscita dello strumento esterno o usare un loopback: il MIDI non contiene audio. Monitoring ingresso disattivato per evitare feedback.

Accettazione ancora necessaria: dispositivi fisici Windows/macOS/Linux, endpoint UMP e driver effettivi, latenza round-trip, plugin dell’utente e server EL10/LXC/HAProxy, incluso Landlock. Nessun commit/push/tag/release o modifica al server di produzione. Risultati eseguiti in validation/r210-vst3-completion-result.json.

## EN

Original server editors stream the authentic Linux plugin UI from an authenticated worker-private display. Mouse/keyboard/wheel target the same playback or VSTi monitoring instance; opening while stopped prepares a paused session. Closing saves state with ownership, quota and conflict checks. Expiry attempts a final save. A hung plugin can still lose unsaved changes. No public VNC, clipboard channel or executable upload is exposed.

RPM/DEB include a private Xvfb 21.1.24 built from SHA-256-pinned official source, avoiding the missing EL10 distribution package and third-party repositories. Its manifest and MIT/X11 licence ship in the package. Docker uses the distribution Xvfb; libXtst is included. Linux Landlock ABI >=3 must be allowed by the host/container. The GUI worker scrubs server credentials and confines filesystem access to runtime resources, trusted plugins, authorized source audio and private temporary files. Without confinement the original editor is unavailable. This validation environment lacks AF_UNIX and Landlock, so graphical integration uses an explicit test-only authenticated TCP display and confinement bypass. Do not set MTA_VST3_DISPLAY_TEST_TCP in production; actual confinement still requires deployment acceptance.

The pinned Pedalboard/JUCE 0.9.26+mta2 host adds continuous PPQ across zoned/adaptive tempo maps, auxiliary sidechain buses and full-resolution mapped UMP events. Packaging builds it ahead of time and hashes all patch inputs. Sidechains tap the selected track after input gain, before inserts/fader, and use the same graph for live and offline rendering. Select C++ to use them.

SMF 0/1 preserves bounded complete SysEx without replaying it on seek. Hardware SysEx requires explicit permission. MPE lower/upper zones configure RPNs and allocate member channels. Native libremidi exposes actual OS UMP endpoints; no endpoint means no native MIDI 2 device. MTA UMP JSON retains original words/timing and is not standard SMF2. The VST3 mapping preserves 16-bit velocity and 32-bit expression/controller resolution for supported event types; unsupported mappings fail explicitly, and plugin note-expression support is still required. Per-note pitch uses the default 48-semitone range. Raw hardware UMP transport remains lossless. SMF2/SMPTE and a dedicated ASIO selector remain outside scope.

The red transport recording button captures client audio, not server hardware: native C++ SPSC ring or browser AudioWorklet, selected input, latency compensation and optional playback. Connect an external instrument audio/loopback input; MIDI itself contains no sound. Stereo float packets have bounded sizes and strict sequence checks. Recording defaults to 512 MiB, at most one hour, one per user/sixteen globally; abandoned uploads expire after 45 seconds. Quotas apply, and the established durable import transaction publishes the recorded track before reporting completion. Input monitoring stays disabled to prevent feedback.

Physical-device, driver, UMP endpoint, round-trip latency, third-party plugin and production EL10/LXC/HAProxy acceptance remain required. No commit, push, tag, release or production mutation was performed. See validation/r210-vst3-completion-result.json for actual test results.
