# VSTi / MIDI - MTA Audio Editor 0.3.0-r210

## Italiano

Da EDIT / IMPORT / MIX scegliere MIDI / VSTi per una traccia vuota, oppure Import MIDI per un file Standard MIDI File (.mid/.midi, tipo 0 o 1, massimo 8 MiB). I messaggi dei vari canali sono uniti in una traccia, conservando il timing originale anche con cambi di tempo. La griglia usa il BPM del metronomo/progetto; importare un MIDI non rallenta o velocizza l'audio esistente. Il progetto conserva note, controlli, strumento, parametri e stato VST3. I binari dei plugin non sono incorporati negli archivi.

Nell'editor MIDI scegliere uno strumento installato e premere Carica strumento: un effetto audio non viene accettato come VSTi. Sul server l'amministratore installa strumenti Linux compatibili nelle directory VST3 configurate, fuori dai dati modificabili dagli utenti. Nelle app native si usano i plugin della stessa piattaforma/architettura dell'app. Per l'hosting continuo scegliere C++ nelle impostazioni della propria app oppure in Web App sul server. Rimane disponibile il motore corrente, con rendering offline delle note.

Il piano roll si apre anche con doppio click sulla traccia o dal menu contestuale MIDI / Strumento VST. Doppio click sulla griglia aggiunge una nota; trascinamento e bordo destro spostano/ridimensionano con snap. Una nota selezionata espone pitch MIDI 0-127, inizio e durata in millisecondi, velocity 1-127 e canale 1-16. Salva MIDI rende persistenti le modifiche; Salva e riproduci progetto applica la bozza e avvia l'ascolto. I parametri dello strumento hanno cursori normalizzati. Nelle app native e disponibile anche l'editor originale dello strumento; salvare prima di aprirlo. Sul server si usano i controlli web.

Il segnale segue: eventi MIDI -> VSTi -> gain -> insert di traccia -> fader/pan/mute/solo -> insert master -> fader/fade master. La traccia puo essere duplicata, spostata/ritagliata nella timeline, esportata come SMF o convertita con Bounce su traccia. Esportazione e bounce audio includono lo strumento e gli effetti. L'export MIDI contiene eventi e misura/BPM correnti, non audio, preset o binari VST3.

Pausa/ripresa e seek utilizzano il clock del trasporto. Al salto vengono azzerate le voci precedenti e ripristinati controlli, pitch bend, programma, note tenute e note sostenute dal pedale; la fase dell'oscillatore e le code precedenti non vengono ricostruite. I confini dei clip rilasciano sustain e note per evitare voci bloccate. Sul server l'audio viene inviato al browser come PCM autenticato; non viene aperto un dispositivo sul server. La riproduzione normale usa un buffer piu ampio del bus interattivo separato.

Registra ingresso MIDI usa Web MIDI nel browser (HTTPS/localhost e autorizzazione) oppure RtMidi nelle app native. Collega dispositivi MIDI permette di scegliere ingresso e uscita. Avvia monitoring attiva un bus separato con il VSTi anche a transport fermo; la tastiera sullo schermo funziona senza hardware. Sul server i blocchi stereo da 1024 campioni viaggiano via WebSocket autenticato: il buffer e il round trip sono mostrati e la latenza di rete resta inevitabile. Il percorso nativo usa il dispositivo C++ e code limitate fuori dalla callback. Panic, chiusura, cambio progetto o disconnessione rilasciano le note. La registrazione salva una bozza da tempo zero e non acquisisce l'audio esterno.

Destinazione MIDI permette VSTi, MIDI hardware o entrambi. La porta locale e salvata per utente/progetto e deve essere selezionata prima della riproduzione. Il server non apre porte MIDI dell'hypervisor: il browser invia al dispositivo dell'utente. Il sequencer nativo segue il contatore del dispositivo C++; quello web usa timestamp Web MIDI e un anticipo limitato. Sono inviati note, controlli, program change, pitch bend e, opzionalmente, MIDI Clock 24 PPQ con Start/Continue/Stop e Song Position. Seek ripristina note tenute e sustain. L'audio di strumenti esterni non compare in bounce/export; per includerlo occorre acquisirlo separatamente. Una porta/canale condiviso puo essere interessato dal Panic di un'altra traccia.

Il runtime compilato Pedalboard 0.9.26+mta1 fornisce a strumenti ed effetti JUCE/VST3 BPM decimali, firma metrica, campioni, secondi, PPQ, inizio battuta e stato play/pausa/loop. Il clock segue il dominio sorgente prima del time stretching, evitando un doppio cambio di tempo; gli export condividono il contesto del progetto. Il bus di monitoring segue il cursore del progetto con un aggiornamento di contesto ogni 200 ms. La griglia metronomo statica e supportata; non viene sintetizzata una tempo map dai metronomi adattivi o a zone. I flag loop sono metadati host e non attivano da soli il loop del transport.

Limiti: massimo 64 tracce live, 50.000 note e 100.000 controlli per traccia, 150.000 eventi espansi e 24 ore. SysEx, MIDI 2.0/MPE dedicato, SMF asincrono tipo 2/SMPTE e sidechain esterno restano esclusi. Le code DSP/rete e il sistema operativo non garantiscono hard real time. Nessun dato di billing AI viene inventato per il DSP.

Compatibilita: verificati localmente Surge XT VST3 Linux reale, CHOWTapeModel come effetto, rendering offline, grafo continuo server, transport nativo su backend nullo di test e Chromium con HTTP/WebAudio reali. Queste prove non certificano uscita hardware Windows/macOS, EL10/HAProxy di produzione o ogni plugin commerciale. I plugin restano codice nativo fidato installato dall'amministratore; l'isolamento in sottoprocesso non costituisce una sandbox di sicurezza del sistema operativo.

## English

Choose MIDI / VSTi under EDIT / IMPORT / MIX for an empty track, or Import MIDI for Standard MIDI Files (.mid/.midi, type 0 or 1, up to 8 MiB). Channels are merged into one track, retaining original timing including tempo changes. The editor grid follows the metronome/project BPM; MIDI import does not retime existing audio. Notes, controllers, instrument parameters and VST3 state persist in the project. Plugin binaries are not embedded.

Select an installed instrument and press Load instrument; audio effects are rejected as VSTi. The server administrator installs compatible Linux instruments in trusted VST3 directories outside user-writable project data. Native apps use plugins matching their platform and architecture. Select C++ in application settings or the server Web App settings for continuous hosting. The existing engine remains available with offline MIDI rendering.

Double-click a track or choose MIDI / VST instrument from its context menu. Double-click the piano roll to add a note; drag it or its right edge to move/resize with snap. Selected notes expose MIDI pitch 0-127, start/duration in milliseconds, velocity 1-127 and channel 1-16. Save MIDI persists the draft; Save and play project saves and starts playback. Generic normalized parameter sliders work everywhere. Native apps additionally offer the instrument's original editor; save before opening it. The server uses browser parameter controls.

Routing is MIDI -> instrument -> gain -> track inserts -> fader/pan/mute/solo -> master inserts -> master fader/fades. Timeline clips and delay apply to notes; duplication, audio bounce, audio export and SMF export are supported. MIDI export contains events and the current BPM/time signature, not audio, presets or VST binaries.

Seeking resets previous voices and restores controllers, pitch bend, program, held notes and pedal-sustained voices. Oscillator phase and previous effect tails are not reconstructed. Clip boundaries release sustain and notes. Server playback streams authenticated PCM to the browser without opening a server sound device; normal playback uses a larger buffer than the separate interactive monitoring bus.

Record MIDI input uses Web MIDI in browsers (HTTPS/localhost and permission) or RtMidi in native apps. Connect MIDI devices selects input/output. Start monitoring opens a separate VSTi audition bus, including while transport is stopped; the on-screen keyboard works without hardware. The server streams authenticated 1024-frame stereo blocks over WebSocket, displaying queued audio and round-trip latency; network latency remains. Native monitoring uses the C++ device and bounded queues outside the callback. Panic, close, project changes and disconnects release notes. Recording saves a draft from source time zero and does not capture external audio.

MIDI destination offers VSTi, hardware MIDI or both. The local port preference is stored per user/project and must be selected before playback. The server never opens hypervisor MIDI ports: the browser sends to the user's hardware. The native sequencer follows the C++ device counter; the browser uses Web MIDI timestamps and bounded lookahead. Notes, controllers, program changes, pitch bend and optional 24 PPQ MIDI Clock/Start/Continue/Stop/Song Position are sent. Seek restores held notes and sustain. External instrument audio is absent from bounce/audio exports and requires separate capture. Panic may affect another track sharing the same port/channel.

The compiled Pedalboard 0.9.26+mta1 host supplies JUCE/VST3 instruments and effects with decimal BPM, time signature, samples, seconds, PPQ, bar start and playing/paused/loop flags. Timing follows the source domain before time stretching to avoid applying tempo twice; exports share the project context. The monitor bus follows the project cursor with a 200 ms context refresh. The static metronome grid is supported; no tempo map is synthesized from adaptive/zoned metronomes. Loop flags are host metadata and do not themselves enable transport looping.

Limits: 64 live tracks, 50,000 notes, 100,000 controllers, 150,000 expanded events and 24 hours. SysEx, dedicated MIDI 2.0/MPE, asynchronous type 2/SMPTE SMF and external sidechains remain excluded. DSP/network queues and operating systems do not guarantee hard real time. Musical DSP creates no invented AI billing.

Local tests use actual Linux Surge XT, CHOWTapeModel, offline rendering, persistent server hosting, native null test transport and real Chromium/HTTP/WebAudio. Windows/macOS physical output, production EL10/HAProxy and arbitrary commercial plugins still require acceptance tests. Administrators install trusted native code: subprocess isolation is not an OS security sandbox.
