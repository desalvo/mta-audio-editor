# Shared-project collaboration security review — 2026-11-03

Scope: `app/project_collaboration.py`, its browser client/CSS, the collaboration revision field and storage hooks, and the explicit `app.main` integration. This is a review of this functional change, not a grant for AI models or an acceptance of deployed targets.

## Authority and privacy

- Every discussion/read/stream/media/leave route requires a registered server session and actual owner/recipient membership. An administrator who is not a participant does not gain private dashboard access. Native/development zero-ID sessions are rejected. Main's existing mutation CSRF and common service-admission middleware remain required and are exercised through the real app in integration tests.
- SSE rechecks session and membership on every update; file delivery checks again at request time. **Review finding corrected:** unlike the older shared-project helper, the first dashboard implementation had omitted the owner's account lifecycle state. Deleted/deleting actors and deleted/deleting owners are now denied, and pending notifications for a deleted owner are cancelled. Tests cover both actor/owner denial and cancelled outbox delivery.
- User input cannot choose sender, recipients, stored filenames, storage directories or MIME. Text is a bounded 20,000-character string. Sender identity is captured server-side; display text is escaped in HTML, participant names use `textContent`, and server-generated author colors are also syntax-checked by the client. HTML and style injection are tested against production JavaScript.
- SQLite parameters bind all data values. Table/column identifiers and SQL statements are fixed application text. The project ID is validated by storage; message media IDs are server-generated 32-character hex. Symbolic links are rejected for sidecars and media paths. Discussion DB and media files use private permissions.

## Files, transport and lifecycle

- Uploads are streamed with a 20 MiB cap and owner storage checks per chunk. Malformed, SVG, forged-image and non-media payloads are rejected without publishing a message or leaving orphan files. Media signatures are checked before a probe; supported images are verified with Pillow and bounded to 25 megapixels. Audio FFprobe uses a fixed argument array, no shell, file/pipe protocols only, bounded probing and a 15-second timeout; video streams and unsupported/long audio are rejected.
- Media responses require membership and carry private/no-store/nosniff headers. Expired media is unlinked directly; text records retain an expired placeholder until the share ends. Ending the final share removes media, discussion DB and its journal sidecars. Portable export excludes discussion/history/media, and portable import ignores supplied collaboration sidecars.
- SMTP delivery uses the existing configured transport, not a user-controlled arbitrary endpoint. Notifications use a persistent per-message/per-recipient outbox, server-derived participants and stable Message-ID. Author and revoked/deleted recipients are excluded. Subject header line breaks are removed; HTML bodies are escaped. A durable claim serializes sends across processes, and network calls do not hold the editing lock. Tests replace SMTP: no real email was sent. At-least-once recovery after a crash is documented; exactly-once SMTP is not claimed.
- Background maintenance obtains the common periodic service admission for each cycle. SSE connections retire after 20 seconds and reconnect with a fresh admission, so a live dashboard cannot indefinitely prevent drain. No new model, process-accounting or billing exemption path is added.

## Editing concurrency

Revision publication is protected by the existing cross-process project lock and is atomic with `project.json`. Stale recipients cannot overwrite newer snapshots. Owners require an exact saved base revision for three-way merging; missing historical bases fail closed. Independent keyed track/clip edits survive; owner conflict priority applies to the same changed path. Unkeyed lists are intentionally atomic rather than guessed by index. Ownership/sharing and existing AI publication checks remain authoritative in `app.main`.

The browser preserves dirty local state on live updates, keeps pending snapshots when an explicit reload callback refuses while busy, passes force only after confirmation, and merges in-flight local edits with the saved response. Revoked guests cannot autosave; owners retain their access when the final share ends. Production-function tests cover these paths and project switching during a save. A final live-busy correction adds at most one short pending-settlement timer: it waits only while busy, stops for dirty local state, clears obsolete revisions on sync/save, retains refused callbacks without spinning and is cancelled on disconnect. Seven additional production-JavaScript tests exercise settlement without another SSE event. No server authority, transport or model execution boundary is changed by that correction.
