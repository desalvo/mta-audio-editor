## Functional workflow

1. The original economic claim is still acquired by the existing direct/deferred owner. Before Popen, app/worker_cgroup_recovery.py commits an immutable worker_cgroup_scopes binding to the original job/user/worker token hash, supervisor PID/creation identity, machine fingerprint/boot/cgroup namespace, delegated root and exact root/group device/inode. Raw claim tokens are not added to bindings, public reports or URLs. A checked worker_scope_count on the job makes missing scope rows/journal detectable; missing/partial history is never silently recreated.
2. Actual cgroup v2 filesystem identity is verified using fstatfs. Root and group descriptors are pinned using no-follow directory opens, the configured delegated subtree is bounded, generated group names are validated and telemetry/control files are opened relative to the pinned descriptor. A path, generic directory, symlink, old inode or new boot/namespace is not kernel authority. Registration requires a verifiable live supervisor and an empty group.
3. The child bootstrap calls enter_before_exec before executing the worker. BEGIN IMMEDIATE is held across original-supervisor liveness/ownership validation and the cgroup.procs write. Recovery/normal cleanup uses that same ledger lock. If bootstrap wins, it joins before a recovery receipt can commit; if recovery wins, a late bootstrap sees the receipt and refuses to join/exec. This closes the Popen-to-cgroup race. The trusted server package root is passed explicitly so bootstrap does not depend on the worker cwd or import path. Application-owned subsequent scopes require the same original supervisor; tokens do not enable takeover/reinference.
4. All registered direct worker cgroups pass the original job credentials explicitly. The project-audio cgroup branch inherits an active deferred owner automatically, covering that existing Arranger/Remix boundary too. Unowned native/non-economic cgroups keep their prior behavior; that does not certify every non-cgroup, legacy, native or remote executor (B5 open).
5. Normal cleanup terminates a still-running bootstrap first, recursively stops the cgroup, verifies populated=0 and persists a worker_cgroup_receipts record before cgroup removal/measurement return. DB, identity or kernel failure keeps the scope unresolved. Financial finish_job, idempotent retries, claim finish and original job-fence settlement require all counted scopes to have valid receipts. The metering error handler checks this barrier before GPU-slot release or unmetered failure completion. The earlier error path could close a job even if cgroup cleanup failed; that defect is fixed.
6. An authenticated active administrator views registered scopes in settings, explicitly confirms stop and requests quiescence. The service rechecks administrator status and original scope/claim integrity, host/boot/namespace and original supervisor death. A live/unknown supervisor is refused. A reused PID never receives a signal: only the pinned original kernel cgroup is stopped. Recursive cgroup.kill and bounded populated polling precede the immutable proof. Identical retry/concurrent requests return the persisted receipt without duplicate effects. A killed-but-uncommitted attempt stays pending and can be safely retried.
7. Successful administrative quiescence is deliberately NOT economic settlement. Original ledger status, claim/fence, contract reservations, credits and GPU leases remain unchanged for separate financial review. No usage, refund, charge, entitlement, claim transfer or inference is fabricated. A scope proof may later support validated frozen-result delivery, but it cannot create missing metering or authorize a write-off. Full post-crash economic resolution remains missing implementation.
8. The IT/EN admin panel has plain-text data rendering, native confirmation, retained request IDs on retry, error/pending feedback and paginated scope history. The report is read-only, bounded for display but audits the entire journal; older corruption cannot hide beyond page one. Combined readiness reports worker_process_journal_unverifiable/worker_process_quiescence_pending and still cannot enable a switch.
9. Immutable tables participate in existing private account export/retention/erasure. Connection-local mta_worker_erasure permissions require an active administrator and an approved retired non-admin owner; unresolved scopes refuse erasure until their processes are proven quiescent. Other owners/fresh connections retain deletion protection. This extends the existing policy and is not new whole-product privacy certification.

## API and operator use

- GET /api/admin/service-regime/worker-processes?limit=50&offset=0 (limit 1..200).
- POST /api/admin/service-regime/worker-processes/{scope_id}/quiesce with exactly {"request_id":"a-stable-unique-id-of-16-to-100-characters","confirm_stop":true}. Existing session authentication and X-MTA-Request CSRF defenses apply. The request ID accepts ASCII letters/digits/underscore/hyphen.
- No endpoint accepts arbitrary paths, PIDs, tokens or a user-declared death proof. Errors preserve the original economic claim. No new owner/customer controls or regime switching are introduced.

Only successful quiescence receipts are the immutable evidence journal; a failed HTTP attempt is not recorded as a successful stop. A missing/removed cgroup without a prior valid receipt is unknown, not evidence of emptiness. A changed boot/namespace requires separate operator diagnosis. Existing unregistered claims cannot be backfilled from guesses. Recovery is explicit and local, never automatic on startup or based on elapsed time. It does not authenticate remote tasks or prevent a privileged external actor from moving workers out of a delegated hierarchy.
