# Supported ONNX loader binding — 2026-10-26 — PRE-RC

The Basic Pitch adapter and both DiffSinger ONNX sessions (acoustic and vocoder) now pass verified bytes directly to ONNX Runtime. They no longer verify a path and later ask the runtime to reopen it. The shared reader opens without following links where supported, requires a regular single-link bounded file, compares descriptor size/mtime/ctime before and after reading, and hashes the exact returned bytes against the trusted adapter pin or managed inventory hash. Basic Pitch is bounded to64MiB, DiffSinger to the existing4GiB bundle cap. Runtime byte loading requires memory for the model bytes; external ONNX tensor-file discovery is not enabled by this API. CPU providers, thread limits, telemetry configuration and output validation remain unchanged.

A replacement after verification cannot change these runtime inputs. A replacement before reading, same-size tamper, empty/oversized file, symlink, hardlink or directory is refused. This is a direct loading boundary for these supported in-process ONNX sessions, not a claim that arbitrary adapters load selected assets. It does not provide remote process attestation, independent model rights or kernel confinement. Commercial remote inference and regime switching remain disabled.
