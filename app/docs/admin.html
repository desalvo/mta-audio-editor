2. Docker

export MTA_ADMIN_PASSWORD='password-lunga-casuale'
docker compose up -d --build

L'immagine production include FFmpeg e, per default, il plugin Demucs. Il container gira come UID/GID 10001, senza capability e con no-new-privileges. La root filesystem è read-only nel deployment consigliato.

Per una build ridotta senza stem splitter:

docker build --build-arg INSTALL_STEMS=false -t mta-audio-editor:core .

3. Kubernetes

Obbligatorio: creare il Secret fuori dal repository. Usare External Secrets, Sealed Secrets, Vault o equivalente negli ambienti reali.
kubectl create secret generic mta-audio-editor-auth \
  --from-literal=username=admin \
  --from-literal=password='password-lunga-casuale'
kubectl apply -f k8s/deployment.yaml

Il PVC montato su /data/projects contiene anche la cache Demucs/Torch, così i modelli non devono essere riscaricati a ogni restart.

5. Demucs/stem plugin

Il registry plugin espone stato e modelli supportati. L'adapter Demucs esegue il comando con argv fisso, senza shell. I modelli consentiti sono htdemucs, htdemucs_ft e htdemucs_6s. Il modello 6-stems è raccomandato quando sono richiesti guitar e piano separati.

Il primo utilizzo può richiedere accesso a Internet per ottenere i pesi. In cluster air-gapped predisporre la cache sul PVC prima dell'avvio operativo.

6. Pipeline audio e plugin

Gli insert sono mappati esclusivamente a preset FFmpeg presenti in un allow-list server-side. Il client non può inviare espressioni FFmpeg arbitrarie. Ogni traccia può avere fino a 16 insert EQ/normalizer/compressor/limiter. Il master applica una seconda catena separata sugli export stereo e sulle preview.

ExportPipeline
MTAClip → insert traccia → fader/pan → stream separati → container Matroska/MTA.
WAV/MP3Clip → insert traccia → fader/pan → summing → master fader → master inserts → encode.

8. CI/CD

Figura 2 - Gate obbligatori prima della pubblicazione.

Quality, test/coverage, Ruff, Bandit, pip-audit, Gitleaks, Trivy filesystem/image, container smoke test e CodeQL. Un push su main pubblica desalvo/mta-audio-editor:latest; un tag pubblica lo stesso tag. Le immagini sono amd64/arm64 con SBOM e provenance.

9. Operazioni

  • Terminare TLS su Ingress/reverse proxy.
  • Monitorare spazio PVC: sorgenti audio, export e cache modello possono occupare molto spazio.
  • Dimensionare CPU/RAM in base alla separazione stems; Demucs è sensibilmente più pesante del normale editing.
  • Centralizzare i log e monitorare probe/restart.
  • Mantenere aggiornati base image e dipendenze tramite Dependabot e gate.

10. Backup/restore

Eseguire snapshot/backup coerenti del PVC. Il dato essenziale è /data/projects. La sottodirectory .cache può essere esclusa per ridurre il backup, sapendo che i modelli dovranno essere riscaricati o ripristinati separatamente.

12. Responsabilità production

La baseline include hardening, test e gate automatizzati. Restano responsabilità dell'operatore: TLS, segreti, backup, monitoraggio, network policy, capacity planning, patch management e validazione funzionale sui dispositivi MTA reali. La compatibilità bit-perfect con metadati proprietari Merish non documentati non è dichiarata.
