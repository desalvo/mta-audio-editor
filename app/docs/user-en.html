MTA Audio Editor is a true multitrack Digital Audio Workstation (DAW) and does not require a project to be constrained to an MTA format. The Multitrack DAW project format is intended for unrestricted editing, mixing, effects and mastering; MTA8 and MTA16 remain available as dedicated project formats and export targets.

MTA means Multi Track Audio: a multitrack container that keeps musical parts separately addressable during playback. MTA Audio Editor can import and edit existing files, but it can also create new MTA8/MTA16 files from tracks or stems and export the completed project as MTA, WAV, MP3, MP3+G or FLAC; individual tracks can be exported separately as WAV, MP3 or FLAC.

This manual covers the complete MTA Audio Editor workflow: access and platforms, projects, import, waveforms, editing, synchronization, mixing, effects, musical metadata, stem separation, MTA8/MTA16 export, desktop clients and mobile apps. Procedures include screenshots, diagrams and practical examples.

1. Quick start

Start by choosing how the project is created: empty, imported from an existing MTA, built from individual audio files, or generated from a stereo mix through stem separation. If the final destination is MTA, also choose MTA8/MTA16 and the target device profile.

Figure 1 - Project lifecycle. Source audio remains available while clips, events and processing are edited non-destructively.
Open or create. Use New project, Import MTA or Open project.
Inspect tracks. Check names, roles, synchronization, channels and waveforms.
Edit and mix. Work with the timeline, faders, pan, mute/solo and inserts while playing.
Check Render. Compare dynamic preview with the rendered master.
Export. Select the device profile and verify Click/Melody and slot mapping.

3.1 Main panels

The Timeline manages clips and time selection. The Inspector edits the selected track. The Mixer provides a compact view of tracks and master. The larger vertical fader is the volume control; adjacent meters are reserved for realtime signal level, so no redundant static level bar is shown. Lyrics/Chords/Markers manage timed musical events.

3.2 Selection and state

The selected track provides context for insert editing, import/replace, split and single-track export. Mute, Solo, level, pan and FX state remain available in the mixer.

4. Projects, archives and autosave

The Multitrack DAW format is the recommended default for general editing and mixing: it does not constrain the project to 8 or 16 tracks. WAV, MP3, MP3+G and FLAC export directly; when MTA export is selected, MTA8 or MTA16 is chosen and slot mapping is applied only for that output.

A project stores tracks, clips, waveform previews, events, inserts, mix settings, target format, MTA profile, view state and metadata. Source files and required attachments remain in the project workspace.

New desktop project. Choose a name and save destination; the local archive is bound to the project.
Desktop MTA import. A project destination is selected before import starts. Cancelling the dialog cancels the import.
Autosave. Changes are automatically persisted when enabled; manual Save remains available.
Project Info. Project/File - Project Info shows name, project ID, home/workspace, location, target, duration, track count, artist, BPM, key and MTA profile.
Project archive versus MTA export: the project archive contains editing information that does not necessarily belong in the final MTA.

5. MTA and audio import

MTA import creates editor tracks from the available audio streams, reads usable names/roles and supported attachments, and keeps the original source. Audio import can add a new track or replace the selected track.

Example: select Guitar, choose Import & Replace, check the entry point and Solo it with drums and bass. Fine-tune any offset by moving the track or editing its clip.

6. Waveforms and cache

Waveforms are graphical previews, not the audio source. They are calculated when required, stored in the project with a revision and loaded immediately when a project is reopened. Changes that invalidate the preview trigger recalculation.

Important: playback does not depend on waveform availability. Audio can play while waveform generation is still in progress.

7. Transport, buffering, synchronization and Follow

Figure 3 - Dynamic preview startup and synchronization.

The |◀ control returns the transport and active sources to 00:00.000. Rewind/forward change position; Play starts or resumes; Pause keeps the current position; Stop closes the current preview session.

7.1 Dynamic preview

Before playback, all tracks are prepared and buffered. The UI reports Buffering audio... please wait and then synchronization. Playback starts only when sources are ready. A reference clock monitors drift and realigns active sources when necessary.

7.2 Render mode

Render plays a backend-generated master preview. Browser-live parameters remain immediate; changes that are baked into the master trigger an automatic refresh at the current position without a manual Stop/Play cycle.

7.3 Follow

Follow keeps the playhead visible in both dynamic and Render modes. In Render mode the rendered master explicitly acts as the transport clock.

9. Tracks, roles and MTA slots

Each track contains name, role/type, source, clips, channel information, volume, pan, mute/solo, inserts, waveform state and an assigned MTA slot. The Inspector exposes an editable MTA Slot field: Auto delegates placement to the device profile, while 1...8 or 1...16 stores the preferred output slot. The value is reused as the initial export mapping and is updated when the user confirms a mapping. Multiple tracks may share a slot when they must be mixed into one MTA output stream. Track roles remain important to Auto Mix and mapping; click identifies the metronome and melody the guide melody.

Click identification: explicit metadata and track name/role are preferred. Stream position alone is not sufficient because MTA8 device families use different Click/Melody orders.

Fixed and adaptive metronome

Metronome generates a click at the project BPM. Adaptive is intended for songs with accelerando, ritardando or internal tempo changes: every request reanalyses the complete current song from scratch, excludes any existing click track from detection, rebuilds a beat-by-beat tempo map and regenerates the click on the detected beats. A previous adaptive map is never reused.

10. Live mixer and VU meters

Figure 5 - Mixer and meters.

Track level, pan, mute/unmute, solo/unsolo and FX state can be changed while playback continues. Global Mute/Unmute, Solo/Unsolo and FX Bypass/Enable controls simplify mix comparisons.

RealTime meters monitor both tracks and master. In Render mode the per-track analyser path is separated from speaker output, so the master can remain the only audible stream while track meters still receive the real signal.

Balancing example: start playback, establish drums as a reference, balance bass and instruments, use Pan to create space, then check the master. No Stop/Play cycle is required for these changes.

11. Insert FX, presets and controls

Tracks and master support chains of up to 16 inserts. Available processors include normalization, compression, limiting, Delay, Lexicon-style Reverb, Room/Ambience, 32-band Graphic EQ, Amplify, Stereo Imager, Maximizer/Loudness, Mastering Wizard, De-Noise and Crackling Cleaner.

OperationWhile playing
Bypass / EnableApplied automatically
Preset changeThe affected preview is refreshed
Custom parametersPersisted and applied
Add / remove insertThe chain updates without manual Stop/Play
Figure 6 - Real plugin editor: preset selection immediately refreshes the visible parameters and continuous values expose synchronized knob and numeric controls.

Changing a preset updates the plugin's visible parameters immediately to values appropriate for that preset: for example Slapback selects a short delay, Large Hall increases reverb size/mix, Wide increases stereo width and Strong raises noise/crackle reduction. Continuous parameters use a synchronized rotary knob plus numeric input; moving either control updates the other. A knob commits the value when the adjustment is released; a numeric input commits directly when Enter is pressed or when focus leaves the field. The 32-band graphic EQ keeps its dedicated faders. Factory presets can be complemented by user presets, and all parameters are validated by the backend.

12. Auto Mix and master

Auto Mix applies deterministic, role-aware balancing rules to track gains, pan and processing. It is reversible: enabling it stores a snapshot and disabling it restores that previous state.

Recommended workflow: use Auto Mix as a starting point, then manually refine the result while checking guide vocal/melody, Click, master dynamics and the densest sections of the song.

13. Lyrics, Chords and Markers

Lyrics, Chords and Markers are timed project events. Lyrics can be extracted with Whisper large-v3 with word-level timing; chords prefer Chordino/NNLS-Chroma when available and fall back to the internal harmonic analyser. They remain editable, are saved in the project and MTA exports, can be downloaded as text, and can be rendered to PDF with a selectable chord color.

Example: add Intro, Verse, Chorus and Solo markers, timed chord symbols and lyric lines. A global song cut shifts later events together with the audio.

14. Stem separation

Import & Separate uses Demucs and can optionally extract synchronized lyrics and chords in the same workflow. For higher accuracy, lyrics extraction uses the isolated Vocals stem when available, while chord analysis uses the original mix. Stems, lyrics and chords are saved into the project and carried into MTA exports.

Select the stereo source.
Choose Multitrack DAW, MTA8, MTA16 or the current project.
Wait for server progress.
Rename and classify generated stems.
Add Click/Melody if available and synchronize.

15. MTA8/MTA16 and device profiles

Figure 7 - Physical Click/Melody positions used by export profiles.

MTA (Multi Track Audio) is a multitrack format containing audio streams plus metadata/attachments. Device-specific export must preserve the real stream position, not only an internal logical slot label.

ProfileClickMelodyBehavior
Merish5 / Xynthia2 - MTA887Physical positions preserved
B.Beat / B.Beat Plus / Evo / Pro16 / DIVO - MTA878Physical positions preserved
M-Live MTA16 - corpus default19Suggested and always editable
Generic MTAManualNo device-specific assumption
MTA16: the available MTA16 samples consistently place Metronome in stream 1. Explicit Melody Track appears most often in stream 9 and in one sample in stream 10, so slot 9 is a practical default rather than a universal requirement.

16. MTA creation, export and slot mapping

Figure 8 - Real Export panel.

The application can create a new MTA8 or MTA16 from scratch as well as modify an imported MTA. A completed project can be exported as MTA, WAV, MP3, MP3+G, FLAC or karaoke MP4, while each individual track can be exported separately as WAV, MP3 or FLAC. MP4 export is enabled only when synchronized lyrics exist and can use either a black background or an optional JPG/PNG/WEBP image; word-level timing is used for karaoke highlighting when available. For MTA, select the device profile and verify slot mapping. When a project contains more tracks than the MTA capacity, multiple project tracks can be assigned to one output slot and mixed before container generation.

Choose MTA8 or MTA16.
Select the target device profile.
Check Click and Melody roles.
Review or customize slot mapping.
Export and test the result on the target device/firmware before live use.
Silent slots: when needed, export creates silent intermediate streams to preserve a physical position. Without them, an item assigned to slot 9 could become the fourth real stream.

18. Windows and macOS

Desktop clients run the local backend and native WebView. File choosers are provided by the operating system. macOS packages target both Intel and Apple Silicon; Windows can be packaged with an installer.

A local project archive binding is persisted across restarts. Save As can change its path. Native import/upload limits are configurable in Settings.

19. Accounts, TOTP, security and sharing

Users, passwords, TOTP, email verification, roles and sharing apply to the online/server edition and to mobile apps. Mobile apps connect to a cloud/remote server because heavy operations - FFmpeg rendering, MTA generation, waveform work and Demucs separation - run server-side; therefore they use the server account. In local native/desktop single-user mode authentication features are unnecessary and hidden, and processing/files stay on the user's computer.

Recommendation: public servers should use HTTPS, strong passwords, TOTP where appropriate, regular persistent-volume backups and upgrades validated through the production gate.

Stem count

Stem separation offers Auto / 2 / 4 / 6 / 8. Auto is the default. The current iPhone/iPad build performs Demucs on the server; 8 stems requires a compatible extended backend model.

On-device Demucs on iPhone/iPad. Auto mode uses Core ML on the device when a compatible local model is available and falls back to the server otherwise. Models can be downloaded once from the server and reused offline. The current conservative on-device limit is 12 minutes per source file; longer material is processed by the server in Auto mode.

Native updates and Demucs models

Native Windows, macOS, Android, iPhone and iPad applications check GitHub for newer versions. The Stable channel uses tagged releases only, while Early release also includes the rolling early-main prerelease produced by the latest successful main build.

On iPhone/iPad the app automatically provisions a default 4-stem Demucs Core ML model: it prefers a bundled validated model and otherwise downloads it from the configured server. SHA-256 fingerprints are compared with the server inventory and installed models are refreshed when the fingerprint changes. Once installed, the local model remains available offline.

On iOS/iPadOS application updates must still use TestFlight/App Store or another operating-system-authorized distribution mechanism.

Automatic mobile Demucs model updates

The Docker/Kubernetes server periodically refreshes Core ML (iPhone/iPad) and ONNX (Android) model repositories from an HTTPS manifest, verifies SHA-256 and replaces files atomically. Mobile clients check the catalogue every six hours and at startup. Update on Wi-Fi only is enabled by default, so periodic model updates download only over Wi-Fi unless the switch is explicitly disabled. The baseline 4-stem model is provisioned at the first available network opportunity.

Model-driven stem separation

Stem counts are no longer limited to 2/4/6/8. The list is generated from models actually available on the server or installed on the device and may include 10, 12, 16, or more stems. Multitrack DAW projects keep all tracks; MTA8/MTA16 constraints are handled only during export.

Dynamic Demucs model management

The server periodically refreshes the full configured model catalogue, including official Demucs models available in the runtime and Core ML/ONNX artifacts published by the manifest. Mobile and desktop clients download the selected model on demand when splitting is requested. Local options can delete, re-download, or force-update one or more models. Administrators can blacklist a model: managed server artifacts are deleted and the model disappears from the web/client catalogue until it is removed from the blacklist.

AI model authentication

Demucs downloads use revocable runtime tokens scoped to models:read, separate from administrator privileges. Mobile apps obtain and renew the token automatically after a valid session.

Synchronized Lyrics and Chords

Use a track's context menu and choose Extract lyrics or Extract chords. Detected events are remapped to the track's actual project timeline, so offsets, clips and cuts are respected. Lyrics and chords become independent project data and remain available if the source track is later edited.

Lyrics can be downloaded as plain text, synchronized text with chords, or as a PDF. The PDF places chords above lyric lines and, when available in Project Info, shows title and author/performer at the top. MTA export embeds a lossless synchronized-event representation so the data stays inside the file and can round-trip back into the project.

Lyrics extraction: uses local/upstream OpenAI Whisper when the optional engine is installed. Chords are analysed locally by the built-in engine.

High-accuracy Lyrics/Chords and karaoke video

Import & Separate can extract lyrics and/or chords in the same workflow. Lyrics use Whisper in high-accuracy mode (large-v3 by default, beam search and word-level timestamps). Chords prefer Chordino/NNLS-Chroma when available and fall back to the built-in harmonic analyser.

The Lyrics + Chords PDF lets the user choose a chord colour. MP4 Karaoke export renders the project mix audio with synchronized lyrics; an optional JPG/PNG/WEBP background image can be used and chords can also be displayed above the lyrics. MP4 export is unavailable when synchronized lyrics are missing.

ChordPro and author-society repertoires

Synchronized lyrics and chords can also be exported as ChordPro (.cho): title, artist, writers, key and BPM are emitted as ChordPro directives, while chord symbols are aligned into the lyrics using word-level timestamps when available.

Project Info can store original title and writers/composers and provides Search rights repertoires. SIAE and Soundreef are selected by default. When an official/licensed structured endpoint is configured, candidate works are shown directly and one or more can be selected; when no documented public API is available, the app links to the official repertoire and allows a verified result to be recorded manually. Selected records (society, original title, writers/performers, publishers and identifiers such as ISWC/IPI/work ID) are stored in the project, embedded in MTA exports and printed at the end of Lyrics + Chords PDFs.

M-Live / Merish MP3 export

The output formats include M-Live / Merish MP3, producing a normal MP3 with synchronized lyrics, chords and markers in ID3v2.3/SYLT metadata. Title, performer and authors are embedded when available in Project Info. The technical profile is documented in MTA-Audio-Editor-M-Live-Merish-MP3-Format-Specification-EN.pdf.

Project sample rate and clip conversion

Every project has a fixed sample rate selected at creation time: 44.1 kHz (default), 48 kHz, or 96 kHz. It can be changed from Project Info only while the project has no active tracks. Audio imported at 44.1/48/96 kHz is retained in Originals while the timeline copy is automatically resampled to the project rate when required.

WAV and MP3+G export

WAV export supports 24-bit PCM or 32-bit float at 44.1, 48, or 96 kHz. MP3+G export creates a ZIP containing a same-basename MP3 audio file and CDG graphics file with synchronized karaoke lyrics and chords.
